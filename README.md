# OPD Clinic — Outpatient Management SaaS

Walk-in registration → token queue → consultation → prescription → billing → reporting, for a multi-doctor clinic. One non-negotiable loop, working end-to-end before anything else.

## Stack

Next.js 16 App Router (Server Actions) · TypeScript · PostgreSQL (Neon) + Drizzle ORM · Auth.js v5 credentials + JWT · Tailwind + shadcn/ui + Base UI · React Hook Form + Zod · TanStack Table v9 · pdfcn/Takumi PDFs · Playwright E2E.

Spec: `OPD-SaaS-Spec.md`. Build conventions: `AGENTS.md`. Decision history: `decisions.md`.

## Getting started

```bash
pnpm install
cp .env.example .env   # DATABASE_URL, AUTH_SECRET, AUTH_URL, SMTP_* optional
pnpm db:generate
pnpm db:migrate        # tsx runner, not drizzle-kit
pnpm db:seed           # masters + demo accounts, dev only
pnpm dev               # http://localhost:3000
```

Scripts: `pnpm build`, `pnpm start`, `pnpm lint`, `pnpm tsc --noEmit`.

## Key business rules

- **Token assignment** runs per doctor per day inside a transaction with `SELECT ... FOR UPDATE SKIP LOCKED`, backed by a unique index — simultaneous bookings never collide.
- **Finalized prescriptions are immutable**; corrections need a new version.
- **Role matrix**: receptionists own patients/appointments; doctors own their queue's consultations/prescriptions; admins own masters and reports. Every Server Action checks role first, validates with Zod second.
- **No-show auto-flag** runs on queue render per Settings thresholds (time + token gap).
- Sessions last 8h; deactivation and password changes propagate within ~5 minutes.

## Deploying

Vercel (app) + Neon pooled WebSocket (`-pooler` host — plain `pg` can't run the token transactions). Set `AUTH_SECRET` + `AUTH_URL`, run `pnpm db:migrate`. Never run `pnpm db:seed` in production (refuses unless `SEED_DEMO=1`); create the first admin directly in the database.
